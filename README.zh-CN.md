Estratto Studio 是一个装在用户自己电脑上的数据管理与分析软件，初始版本基于经营分析场景开发。导入你的数据，得到的每一个数都在本机计算、都能追溯来源。大语言模型只读你的问题和表结构，看不到你的数据明细。同时，Estratto Studio 支持 DIY：在 Studio 实验室里用一句话说出你想要的改动，助手会新增或改造看板卡片。

> **状态：技术预览。** 本仓库目前收录第六轮（2026 年 10 月）的机制技术报告和评测成绩，软件源码之后会在这里发布，见「[接下来](#接下来)」。

## 为什么做 Estratto Studio

想好好分析自己的数据，过去有三道门槛：

- **企业级的语义层和 BI 平台**：要云数据仓库、要数据团队先把指标建好、要采购预算。同时，数据云仓意味着数据泄漏或共享的风险。
- **text-to-SQL Agent**：要会 SQL 才能核对它写得对不对，而且它一边探索，一边把你的数据发给模型。
- **通用型 Agent**：需要详细清楚的 Prompt 指令，往往要把大量表格内容读进对话，表越大，花的 Token 越多。

个人和小团队通常前两样都没有，手里只有一堆表格和导出的文件。

**而 Estratto Studio，想把这套企业级的体验门槛降低到个人电脑端：**

- **语义层那样口径统一的指标；**
- **SQL Agent 那样灵活的交流；**
- **BI 工具那样可追溯的结果；**
- **全部装进一个桌面软件里：不需要你会 SQL，不用线上数仓，不用先建模，数据明细不出你的电脑，用你自己想搭配的任何大模型。**

**让每个人都能更便捷、有效地管理和分析自己的数据，以更低的成本洞察更多数据。**

## 工作原理

模型负责读懂，本机负责计算。每个问题都走同一条链路：

| 环节                 | 做什么                                                            | 用不用模型                |
| ------------------ | -------------------------------------------------------------- | -------------------- |
| **① 自动建模**         | 导入时自动生成语义层：出厂词典 544 条指标，认不出的列只发表结构问模型一次，表和表的关系用数据实测。不用人先建模     | 新列才问一次，只发表结构         |
| **② 模型只填配置单**      | 本机先把候选找好（最多 8 个），模型只在里面选，填一张结构化的计算清单（指标、分组、时间、筛选、排名、比较），不写任何数字 | 1 次（不完整可再修 1 次）      |
| **②b 限制级写 SQL 兜底** | 配置单表达不了时才用。模型写一条只读 SQL，要过本机三道关：先拆开检查语句，再只读、断网执行，最后对照语义分档       | 需要时才用，1 次（出错可再修 1 次） |
| **③ 本机确定性计算**      | 每个数都由本机 DuckDB 算出。容易错的规则写死在代码里：比率 = 分子合计 ÷ 分母合计，库存这类时点数取期末     | 不用                   |
| **④ 外发门**          | 发给模型的唯一出口。问数只发表结构和问题；助手只拿汇总，每次最多 60 个数，对象名换成代号（G1、G2…）；每次外发都记账 | —                    |
| **⑤ 事实编号回填**       | 每个数都记成一条事实（F1、F2…）。模型写的文字里只有占位符，数字由本机回填，模型编不出数                 | 不用                   |
| **⑥ 越用越省**         | 存核对过的算法，不存结果。同一个问题再问，本机重算，0 次调用模型；权限、口径或代码一变，旧算法自动作废           | 不用                   |

每题最多调用模型 4 次，每次都只看表结构。

## 成绩

经过 **1,009 道题**的测试，都用同一个模型（DeepSeek v4.1 flash）：

- **168 道开发时没见过的新题**（B5、B6 各 84 道，每个系统只跑一次），答对 90.5%（152/168），是 Text-to-SQL Agent（70/168）的约 2.2 倍；
- **841 道旧题回归**，答对 98.7%（830/841），原来答对的题一题没丢。

<p align="center"><img src="docs/images/zh/acc-all.png" alt="1,009 道题的准确率" width="80%"></p>

下表是其中 B6 那 84 道新题的明细：

| 指标          |   Estratto Studio  | text-to-SQL Agent |     差距     |
| ----------- | :----------------: | :---------------: | :--------: |
| 答对          | **76 / 84（90.5%）** |   31 / 84（36.9%）  | **2.45 倍** |
| 每题 token    |      **1,773**     |       19,945      |  **−91%**  |
| 每题花费        |    **$0.00035**    |      $0.00092     |  **−62%**  |
| 平均每答对一题的花费  |    **$0.00039**    |      $0.00248     |  **−84%**  |
| 发给模型的数据行    |        **0**       |     每步最多 60 行     |      —     |
| 同一问题再问不调用模型 |    **84.5%无需再调**   |     0%（每次都要调用）    |      —     |

- **没见过的题也答得准**：B6 答对 76/84（90.5%），是 Text-to-SQL Agent 的 2.45 倍；另一套新题 B5 也是 76/84。
- **旧题不退步**：841 道旧题答对 830 道——公开题中文 198/200、英文 67/67；内部题 494/500、57/60；dbt、Neo4j 示例题 14/14。原来答对的题一题没丢。
- **复用不会把对的变错**：复用的 266 题里 260 题正确（97.74%）；复用里出错的题，第一次就是错的。
- **安全写在架构里**：
  - 5 种权限绕过方法端到端测试，全部挡住；
  - 596 条模型请求经独立审计，里面没有数据值；
  - 算数的程序连不上网，联网的程序读不到你的数据，都由操作系统沙盒强制。
- **表再大，花费也不涨**：因为不发数据行。

## 里面有什么

| 方面      | 要点                                                                                            |
| ------- | --------------------------------------------------------------------------------------------- |
| 听懂      | 中英双语词典 544 条指标；个人叫法和口径；本机向量模型（随安装包带 bge-small-zh-v1.5，中英混合时用 multilingual-e5-small），本机考试过线才打开 |
| 计算      | DuckDB 加转好类型的当前版本表；求和、平均之外还有 10 种计算方式（指定名次、前 N 名占比、实际 ÷ 计划、按日均能撑几天…）；时间用标准日历库解析               |
| 可信      | 已核 / 待确认 / 未核三档；每个数都有事实编号；有歧义先问，缺字段拒答，不拿别的字段顶替                                                |
| 隐私      | 外发门加数据去向记录；权限范围只能收窄；取值目录里的值不发给模型                                                              |
| 检索（RAG） | 本机检索候选、相关表、记忆、文档段落和按重要程度排好的发现；只给名字和文字建向量，不给数字建                                                |
| 存储      | DuckDB 存数据、算数；SQLite 存记忆、事实编号、报告、复用库和外发记录；全部在你的电脑上                                            |
